# Registro de riesgos del proyecto

Escala de probabilidad e impacto: Alta / Media / Baja. Riesgos ordenados por severidad (probabilidad × impacto) descendente.

| ID | Riesgo | Probabilidad | Impacto | Mitigación |
|---|---|---|---|---|
| R-01 | **Sobrecompromiso de alcance vs. capacidad real.** El backlog `Must` (22h) iguala o supera la capacidad bruta disponible (~21h), sin contar imprevistos. | Alta | Alta | Recorte de alcance ya propuesto y priorizado en `08-roadmap.md` (EPIC-7 primero, luego EPIC-3 simplificado). Revisión de avance al final de cada semana (hitos M1/M2/M3) para decidir recortes con anticipación, no en la última semana. |
| R-02 | **Fidelidad insuficiente del Chain-of-Verification en una sola llamada.** Al ser el mismo modelo autoevaluándose en el mismo turno, puede no detectar sus propias imprecisiones tan bien como una verificación independiente. | Media | Alta | Medido directamente por RAGAS (métrica de fidelidad). Si el resultado es insuficiente, el puerto `VerificationStrategyPort` permite implementar `MultiCallVerificationAdapter` sin rediseño (ver [ADR-0005](adr/0005-chain-of-verification-strategy.md)) — aunque su implementación dentro del plazo actual es poco probable y quedaría como trabajo futuro documentado. |
| R-03 | **Privacidad parcial de los datos enviados a la API de Anthropic.** Las preguntas de los estudiantes y los fragmentos recuperados salen hacia un servicio en la nube de terceros, pese a que ChromaDB es local (ver NFR-07). | Alta (es un hecho, no una posibilidad) | Media | Riesgo aceptado y documentado explícitamente (no hay presupuesto ni tiempo para un LLM local, ver [ADR-0006](adr/0006-configurable-llm-model-selection.md)). Se recomienda que el equipo confirme con el asesor que este nivel de exposición de datos es aceptable para el corpus usado en la demo. |
| R-04 | **Costo de la API de Anthropic excede el presupuesto personal.** Sin control de uso, pruebas repetidas durante el desarrollo y la evaluación RAGAS podrían acumular más gasto del esperado. | Media | Media | Modelo económico por defecto (Haiku 4.5), Chain-of-Verification de una sola llamada, y registro de tokens consumidos por solicitud (NFR-02, NFR-05) para monitorear consumo real durante el desarrollo. |
| R-05 | **Ausencia de verificación real de dominio institucional en el registro de usuarios.** El sistema valida el formato `@uvg.edu.gt` pero no verifica que el correo exista o pertenezca a un estudiante activo (ver [ADR-0004](adr/0004-institutional-authentication.md)). | Media | Baja (dado el alcance de demo/tesis) | Aceptado como limitación conocida para esta versión; se documenta explícitamente para no presentarlo como una omisión ante el tribunal. |
| R-06 | **Golden dataset de evaluación demasiado pequeño para ser estadísticamente representativo.** Con el tiempo disponible, es probable construir solo 10-15 pares pregunta/respuesta. | Alta | Media | Se documenta explícitamente el tamaño de la muestra y su limitación en el reporte de evaluación (transparencia académica: una muestra pequeña con resultados honestos es más defendible que una muestra inflada sin rigor). |
| R-07 | **El pipeline de ingesta produce fragmentos "sucios" por artefactos de formato de PDF** (encabezados, pies de página, tablas, doble columna) que la limpieza por regex no cubre completamente. | Media | Media | Prueba manual de la calidad de los fragmentos extraídos contra 2-3 documentos reales antes de dar por completado EPIC-1 (US-1.1 a US-1.3). |
| R-08 | **Deprecación o cambio de disponibilidad de un modelo de Claude durante el proyecto.** Anthropic puede actualizar su catálogo de modelos en cualquier momento. | Baja (ventana de 3 semanas) | Media | El nombre del modelo es 100% configurable vía `ANTHROPIC_MODEL` (ver [ADR-0006](adr/0006-configurable-llm-model-selection.md)); un cambio de modelo no requiere cambio de código. |
| R-09 | **Falla o límite de tasa (rate limit) de la API de Anthropic durante una demo en vivo.** Sin manejo de reintentos/circuit breaker, una falla externa tumbaría la demo completa. | Baja | Alta (durante la defensa específicamente) | Manejo de errores en `AnthropicLLMAdapter` que traduce fallas a un mensaje controlado para el usuario, en vez de un error no controlado; se recomienda tener capturas de pantalla/video de respaldo para la defensa como plan de contingencia. |
| R-10 | **Sin autenticación multifactor ni recuperación de contraseña**, dado el alcance mínimo de EPIC-3. | Baja (alcance de demo) | Baja | Aceptado explícitamente para esta versión; documentado como trabajo futuro, no como descuido. |
| R-11 | **El SDK oficial de Anthropic (línea 1.x) eliminó el parámetro tipado `temperature`.** Descubierto durante la implementación (no documentado por el asesor ni previsible en la fase de arquitectura). Afecta directamente a FR-09. | Media (no se pudo confirmar con una API key real durante la implementación) | Alta (si el servidor llegara a rechazar el envío vía `extra_body`, ninguna respuesta sería determinista) | Se envía `temperature: 0.0` vía `extra_body` (ver addendum en [ADR-0006](adr/0006-configurable-llm-model-selection.md)); una llamada real con credenciales inválidas confirmó que el servidor acepta el campo (401 de autenticación, no error de "campo desconocido"). El equipo debe confirmarlo con una API key real antes de la defensa; si falla, la mitigación de respaldo es fijar `anthropic<1.0`. |
| R-12 | **Vulnerabilidades conocidas en el servidor de desarrollo de Vite/Vitest** (esbuild, path traversal, lectura arbitraria de archivos vía Vitest UI), sin parche disponible en la línea Vite 5.x instalada. | Media | Baja (el build de producción con `vite build`, servido por nginx, nunca ejecuta el servidor de desarrollo vulnerable) | Riesgo aceptado y documentado: son vulnerabilidades exclusivas de `npm run dev` / `vitest --ui`, herramientas de desarrollo que no se usan en la imagen Docker de producción. Actualizar a Vite 6+/Vitest 3+ (cambio mayor no evaluado por el tiempo disponible) queda como trabajo futuro. |

## Riesgos explícitamente fuera de este registro

No se incluyen riesgos de disponibilidad 24/7, escalabilidad a múltiples instancias, ni cumplimiento legal formal de protección de datos, porque el alcance del proyecto (demo local para defensa de tesis, ver [ADR-0007](adr/0007-local-docker-compose-deployment.md)) no los hace aplicables en esta versión. Se documentan como preguntas abiertas para una eventual adopción institucional futura, no como riesgos del proyecto actual.
